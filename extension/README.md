# UMIN-CTR Chrome拡張（練習用・本番の登録前下書き用）

定型DOCXを端末内で解析し、要確認項目を確定してから、新規作成と既存下書きへの転記・照合を行うManifest V3拡張です。Mammoth 1.13.0を同梱します。サーバー・外部AI・ローカル補助アプリは不要です。

## 対応範囲と現在の制限

- UMIN-CTR登録用フォーム Version 1.2.0の23表・210入力項目を対応付けています。
- 利用者が端末のWord等で `.doc` を `.docx` に保存してから読み込みます。`.doc`・`.docm`・マクロ入りDOCX・埋め込みオブジェクトは受け付けません。オンライン変換サービスは使いません。
- 練習用は試用系案内と `https://center6.umin.ac.jp/cgi-bin/ctr_test/`、本番用は本番トップ・新規登録案内と `https://center6.umin.ac.jp/cgi-bin/ctr/` の既知の登録前フォームだけに接続します。各ビルドは他方の環境を拒否します。練習用の `upload.umin.ac.jp` は転送の通過先で、そこでスクリプトを実行しません。
- 本番用も新規作成・登録途中の下書き専用です。受付番号は本番の `R` または練習の `T` と9桁の数字を照合します。`ctr_up_reg_f*.cgi`・`ctr_menu_form_reg.cgi` など登録済み試験の更新画面と最終登録画面は許可しません。本番下書きと登録済み更新は別の操作です。
- BASIC認証は利用者が行います。拡張にIDやパスワードを入力する欄はなく、認証済みのタブを使います。
- 開始位置は2つです。「新規作成」は各環境の案内または空の基本情報画面から、基本情報の転記・照合・個別保存・発行受付番号の照合を行います。本番トップからは新規登録の注意事項ページを経由します。「途中再開」は受付番号のある下書きのフォーム選択画面から開始します。
- 新規基本情報の保存後は、同じDOCXを保持したまま目的以降の段階へ切り替わります。途中再開では基本情報9項目を原稿と照合し、基本情報の上書きは行いません。段階ごとに差分を確認し、1回の実行で入力・照合・個別保存します。
- 機関選択は「その他」が初期設定です。事前照合の最後に管理情報画面を開き、未選択の場合だけ、その画面が開いたポップアップの「その他」を選択して結果を照合します。既存の別機関は上書きしません。「UMIN画面で選択・現在の機関を維持」に切り替えると手動選択できます。Chromeで `center6.umin.ac.jp` のポップアップ許可が必要です（拡張へのアクセス許可とは別設定）。ポップアップを開けない・候補を一意に確認できない場合は、停止理由と対処を表示し、手動選択して再照合できます。実行時は選択を保持した管理情報から保存し、残りのフォームへ進みます。
- 氏名は明確な2語の区切りがある場合に分割候補を表示し、原文と並べて人物ごとに日英6欄をまとめて手動確定します。候補は日本語「姓 名」・英語「名 姓」の順で、逆順・複合姓・ミドルネーム等は利用者が修正します。未対応書式には候補を付けません。専用欄のない郵便番号、公開IRBの英語欄なども手動確定します。
- 年齢は数値・単位・以上以下等が一意な定型表記を直接対応付けます。解釈不能な場合の単位は「歳」を初期候補にしますが、利用者の確認前に確定しません。
- 本文の「■・☑」等、明示的な黄色ハイライト、Wordの箇条書き定義の「■・□」を照合します。文字区間が分割されていても、強調箇所と段落全体が既知の選択肢に一意に一致する場合だけ自動採用します。「□」だけでは未選択確定とはせず、選択記号がなければ手動確認です。
- 自動箇条書きはDOCX内部の定義を直接読みます。既知のUnicode記号と単一階層の十進番号に対応し、開始番号・開始番号の上書き・同じリストの継続・番号後の区切りを保持します。多段階番号、特殊フォントの記号、スタイル由来の番号などは手動確認です。Mammothが付ける既定の番号を転記には使いません。詳細は[書式対応と判断基準](FORMAT_SUPPORT.md)を参照してください。
- 変更履歴、表・ラベルの変更、転記先未定義の「主な結果入力日」の記載などは停止します。既知テンプレートの段落装飾と表プロパティの例外以外の変換警告も、手動確認の対象です。
- 練習用では空の基本情報画面からの新規保存・受付番号引継ぎ・機関2か所の自動選択・目的以降5フォームの一括保存と照合・最終確認手前での停止を実機確認しました。Busy対応と5秒上限のパッチ後にも通し検証が成功しました（その回はBusyの発生なし）。
- 本番の登録前6フォーム・210項目の構造と、新規入口・送信先・戻り先・機関ポップアップを確認済みです。2026年11月17日には、利用者が許可した架空原稿で本番用拡張の新規基本情報保存から開始し、目的以降の保存中にBusyで停止したあと、再開して全フォームの照合完了とフォーム選択画面への復帰を実機確認しました。最終確認・正式登録には進んでいません。各入力画面・確認画面が定義と一致しなければ停止します。
- この実機検証で通常フォームのBusy応答が対象不一致として表示される問題を確認し、Busy専用の停止理由と一覧からの再開案内を追加しました。この追加分は架空画面の回帰テストで検証済みですが、更新後の実機でのBusy再現は未確認です。
- 案内ページからの拡張による通し検証と社内配布・更新方式の確定は未完了です。Issue #2の完了版ではありません。

## ビルドとローカル導入

Node.js 22以降を使用します。リポジトリのルートから実行してください。

```sh
npm --prefix extension ci
npm --prefix extension run check
```

出力は練習用 `extension/dist/` と本番の登録前下書き用 `extension/dist-production/` です。Chromeの `chrome://extensions` でデベロッパーモードを有効にし、「パッケージ化されていない拡張機能を読み込む」から使用する方のフォルダーを指定します。名前とパネル上部に環境を表示します。本番用は「UMIN-CTR 転記補助（本番・登録前）」です。環境を誤らないよう使用する方だけを有効にしてください。社内管理端末の場合は管理方針に従ってください。開発時のこの導入方法は社内一括配布の仕組みとは別です。

配布物にはビルド済みコード・UI・第三者ライセンスだけを含めます。原稿・画面画像・受付番号・入力値は含めません。`templates/`のDOCXも配布物には含めず、公開対象のWordは既存の未記入DOCだけです。

## 使い方

1. 端末内でDOCXへ保存します。変更履歴がある場合は、内容を確認して原稿を確定します。
2. BASIC認証を済ませ、新規作成なら使用する環境の案内ページまたは空の基本情報画面、途中再開なら登録途中の対象のフォーム選択画面を開きます。
3. 対象タブで拡張アイコンを押してサイドパネルを開き、DOCXを読み込みます。
4. 開始位置を選びます。新規作成は基本情報のみ、途中再開は目的以降5フォームが初期対象です。要確認項目を選択・入力して確定します。空欄も転記対象です。既存値を残す場合は「現在のUMINの値を維持する」を選びます。
5. 初回の「事前照合」では、Chromeの確認画面でUMIN登録画面へのアクセスを許可します。拒否した場合は原稿・確認済みの値を保持して停止し、同じボタンから再開できます。許可後に選択したフォームを読み取り、対象試験、現在値を維持する項目、差分・上書きを確認します。この段階では保存しません。管理情報を対象に含めた場合はその入力画面で止まります。「その他」は未選択の場合に自動選択します。手動選択を使う場合、または自動選択で停止した場合は、機関を選び、もう一度事前照合してください。
   初回はChromeのUMIN画面で、サイト設定の「ポップアップとリダイレクト」を許可してください。許可先は `center6.umin.ac.jp` だけです。ブロック後に許可した場合は、開いている機関選択ウインドウを閉じ、管理情報画面の「フォームの選択」で戻ってから事前照合をやり直します。原稿の再読込は不要です。許可済みなら毎回の設定は不要です。拡張はChromeの設定を自動変更しません。
6. 確認チェックを入れ「基本情報を新規保存」または「目的以降を一括入力」を押します。転記、入力値照合、個別フォーム確認、個別保存、保存結果照合を順に行います。
7. 完了後はフォーム選択画面で停止します。「入力内容確認」、データの最終確認、正式登録は操作しません。

事前照合・実行中は対象タブを操作しないでください。別タブに切り替えても転記先は変更されません。パネルを閉じると次の操作は進めませんが、送信済みの保存は取り消せません。

機関ポップアップは読み込み・対象画面・選択結果を順に確認し、準備が整えばすぐ進みます。毎回の固定待機は追加していません。状態確認の待ち上限は5秒です。既知の「Server is busy. Please try again later.」だけが表示された場合は、上限まで待たずに停止し、原稿・確認値を保持して再開手順を表示します。レート制限か一時的な混雑かは判定せず、自動再送・自動選択のやり直しは行いません。

Busy・通信エラー後は少し時間を置き、使用中の環境の案内ページから登録途中の修正・取下げへ進み、「入力中の臨床試験一覧」を開き直してください。対象の下書きのフォーム選択画面で、拡張の開始位置を「基本情報入力済み：目的以降を入力」にし、事前照合から再開します。保存済みの内容と差分を確認してから一括入力し、内容が一致するフォームは再保存しません。画面更新によるフォーム再送信や、拡張による自動再送は行いません。

新規実行後は同じパネルでの再作成を禁止します。保存結果が不明な場合も、まず一覧で保存状態を確認してください。パネルを開いたままなら原稿の再読込は不要です。ブラウザやパネルを閉じた場合は、同じ原稿を再読込します。管理情報を含む事前照合では、未保存の機関選択を保持するため管理情報画面に残ります。そのまま差分を確認し、一括入力へ進んでください。

## データの扱い

- 原稿・確定値・試験識別情報・事前照合結果はパネルのメモリだけに保持します。localStorage・IndexedDB・chrome.storage・ブラウザ同期・テレメトリは使用しません。
- 原稿の変換はWorkerで行い、外部ファイル参照と埋め込みstyle mapを無効にします。変換HTMLを表示DOMへ挿入せず、非表示のinertなtemplateで構造を読み取って必要な値をtextContent等で表示します。
- 拡張ページのCSPは外部接続・画像・外部スクリプト・フォーム送信を禁止します。対象フォームの送信は認証済みUMINタブの既知の個別保存先だけです。
- 原稿の内容をエラーログに出しません。エラーは固定のコードと案内文を表示します。
- 基本権限はactiveTab・scripting・sidePanelです。新規作成・途中再開の事前照合では、サイドパネルの開き方に依存せず対象タブへのアクセスを確立し、新規登録時のドメイン移動も続行するため、任意のホスト権限 `https://center6.umin.ac.jp/*` をChromeの確認画面で要求します。Chromeのホスト権限はパス単位に限定できないため、コード側で各ビルドの環境と既知の登録前パスに制限します。cookies・storage・全サイトの権限は要求しません。
- アプリが作る永続保存を避ける設計です。ブラウザやOS自体によるメモリの退避まで保証するものではありません。

## 構成と検証

- `src/docx.ts`, `parse-worker.ts`：DOCXの形式検査とMammoth変換。
- `src/template.json`, `parser.ts`, `word.ts`：テンプレートの構造検査、項目対応、OOXMLの選択記号・番号・改行の照合、手動確認への振り分け。対応表には定義だけを保存。
- `src/panel.ts`：原稿読込、要確認項目、差分承認、進捗。
- `src/policy.ts`, `content.ts`：対象URL・試験・画面・送信先の検査とフォーム操作。
- `src/transport.ts`, `runner.ts`：固定タブへの通信、事前照合、一括処理、停止。
- 既存スキルの`umin_forms.mjs`・`umin_text.mjs`とJSON定義を共用。Node専用のファイル読込をJSON importへ置換。

テストはコード内で架空DOCX・フォームを生成し、解析、選択競合、マクロ拒否、対象違い、画面変更、差分変更、確認画面の改行欠落、応答不明時の再送禁止を確認します。実資料はテストに使用しません。

```sh
npm --prefix extension run check
node --test skills/fill-umin-registration-draft/scripts/test_umin_forms.mjs
python3 -m unittest discover -s skills/fill-umin-registration-draft/scripts -p 'test_extract_umin_docx.py'
```

ローカルのHTTPプレビューでは原稿読込と編集画面だけ確認できます。タブへの転記はChrome拡張として導入して確認する必要があります。
