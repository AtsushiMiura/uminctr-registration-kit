# Word書式の読み取りと判断基準

Mammothで表の構造を読み取り、OOXMLの本文・段落・番号定義を補助的に照合します。推論モデル、画像認識、外部変換サービスは使いません。対象テンプレートの構造・項目名の照合を緩めず、確定できない項目は既存の手動確認画面へ送ります。

| 表現 | 自動処理する条件 | 確定できない場合 |
| --- | --- | --- |
| 本文の■・☑・☒・✓・✔ | 段落先頭の記号と、既知の選択肢の完全な表記または日本語部分が一致 | 未知の文言、同一段落に複数の選択肢、単一選択で複数候補は手動 |
| 黄色ハイライト | 隣接する黄色の文字区間を結合。強調部分と段落全体の両方が同じ選択肢に一致 | 部分的な強調、黄色以外、スタイル由来の強調は手動 |
| 箇条書き設定の■・□ | `numId → abstractNumId → lvlText` を照合。■等は選択、□単独は選択の証拠にしない。□の項目を黄色で選ぶ形式にも対応 | 定義欠落、特殊フォント、未知の記号は手動 |
| 本文の自動番号 | 単一階層の十進番号、明示的な開始番号、開始番号の上書き、同じnumIdの継続、異なるnumIdの再開始 | 多段階、丸数字・かな番号、スタイルから継承する番号、区切りによる再開始は手動 |
| 本文の箇条書き | 定義が一意な既知のUnicode記号を本文先頭に保持 | Wingdingsなどの字形対応が必要な場合は手動 |
| 改行・タブ | `w:br`・`w:cr`・`w:tab` を直接保持 | 改ページ、段区切り、未対応の本文要素は手動 |
| 非表示文字・文字の表示変換 | 自動採用しない | 原稿で表示内容を確認して確定 |
| 変更履歴 | 本文の挿入削除だけでなく、段落等のプロパティ変更履歴も検出 | 文書全体を停止。利用者がWordで変更履歴を確認・確定 |

番号の途中に解釈不能な項目があると、それ以降の番号も誤る可能性があります。同じ番号定義を使う項目はまとめて手動確認にします。番号・ラベル・値を推測で補完しません。

## さらに手動操作を減らす方法

優先するのは原稿側の規約です。選択肢を1段落に1件とし、本文の■または項目全体の黄色ハイライトに統一すると、特定フォントやWordの内部表現への依存が減ります。自動番号も単一階層の十進番号に限定すれば、現在の実装で扱えます。番号が複雑な原稿は、入力用コピーで表示番号を明示的な文字に変換する方法もありますが、人による照合が必要です。

次に追加するなら、実際に必要な多段階番号・フォントと記号の対応・チェックコントロールの型を限定し、架空データの回帰テストと一緒に対応します。全てのWord書式を再実装する方式は取りません。チェックコントロールは型とチェック状態を直接読める可能性がありますが、表示文字との矛盾や古いフォーム部品があるため、現状は手動確認です。

氏名は姓・名、年齢は数値・単位・以上以下をテンプレート上で分離すると、解釈なしに転記できます。現状は氏名が明確な2語の場合にのみ分割候補を表示し、人物ごとに日英をまとめて確認します。語順を断定して自動確定はしません。年齢は「20歳以上」「6ヶ月未満」等の一意な定型表記を直接対応付けます。曖昧な場合の単位候補は「歳」とし、確認待ちにします。機関選択はUMIN側の候補・識別子との照合が必要で、Word書式の改善とは別に扱います。

ローカルLLM・OCRは、今回の■・黄色・番号の解決には不要です。画面画像から推測するより、DOCX内部の明示的な値を照合する方が再現性と検証可能性を保てます。

## 検証範囲

回帰テストは架空XMLからDOCXを生成し、分割された黄色、本文と番号定義の選択記号、未知のラベル、単一選択の競合、開始番号・継続、未対応の番号、改行の保持、非表示文字、変更履歴の停止を確認します。

別途、書式サンプルの表・段落・文字区間・番号定義を参考に、本文を架空の文言と既知の項目定義だけから再構成したローカルDOCXで確認しました。選択状態も架空に設定し、コメント・削除履歴・作成者情報・外部リンク・添付部品はコピーしていません。生成物はGit対象外の `work/` に置き、配布物やIssueには含めません。

書式検証用ダミーでは210項目中182項目を自動確定し、28項目が手動項目でした。全セクション入りの入力検証用ダミーでは、年齢の定型読取追加後に188項目を自動確定、22項目が手動となり、氏名を人物単位にまとめると画面上の確認は12箇所です。機関2か所の「その他」を自動選択する設定では、確認は10箇所になります。この比率はダミーに対する結果であり、任意の本番原稿の成功率ではありません。Chromeに導入した拡張で、架空原稿による練習環境・本番下書きの全6フォーム保存と照合を確認しました。本番ではBusyによる停止後に再開して完了しています。検証範囲と制限は[README](README.md)を参照してください。

番号定義の解釈はMicrosoftのOpen XML資料の[番号定義の参照](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.numberingid)、[番号文字列と継続](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.leveltext)、[開始番号の上書き](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.startoverridenumberingvalue)、[番号後の区切り](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.levelsuffix)も照合しています。省略された区切りはタブとして保持します。
